## 起因

家里的旧笔记本已经吃灰大半年了。i5-8250U，8G 内存，256G SSD，扔了可惜，卖二手也没人要，正好拿来做自托管服务的载体。

之前各种服务散在好几个地方：VPS 上跑着博客，群晖上放着片子，笔记本里堆着乱七八糟的脚本。管理起来太累，索性全挪到一台机器上，用 Docker 统一管。

## 硬件准备

其实没什么好准备的，旧笔记本本身就是完整设备。

- i5-8250U，4 核 8 线程
- 8G DDR4 内存
- 256G NVMe SSD
- 一块外接 4T 机械盘

唯一要动的是散热。笔记本平放容易积热，买了个铝合金支架撑起来，风扇对着吹，温度能压到 55 度以下。

## 系统安装

### 选发行版

纠结了几天，最后选了 **Debian 12**。理由：

- 稳定，不折腾
- 软件源干净
- Docker 官方支持好
- 内存占用小，8G 机器跑起来够用

Ubuntu Server 其实也行，但最近几年的 snap 让人烦。Arch 太激进，不适合当长期服务机。

### 装系统

用 Ventoy 做个启动盘，插上直接装。

```bash
# 分区方案
/boot   1G   ext4
/       40G  ext4
swap    4G
/home   剩余  ext4

系统装完后第一件事是换国内源，不然 apt update 能等到天荒地老。
bash

sudo sed -i 's/deb.debian.org/mirrors.ustc.edu.cn/g' /etc/apt/sources.list
sudo apt update && sudo apt upgrade -y

Docker 环境
安装 Docker

官方一键脚本，省事。
bash

curl -fsSL https://get.docker.com | sudo bash
sudo usermod -aG docker $USER

重新登录后 docker ps 能跑就说明好了。
安装 Compose

Docker 自带的 docker compose 已经够用，不用再单独装 docker-compose。
bash

docker compose version

服务规划

整理了一下需求，大概分几类：
类别	服务	说明
文件同步	Syncthing	手机、电脑之间同步笔记和照片
媒体库	Jellyfin	看电影、听歌
下载	qBittorrent	BT 下载
相册	Immich	自建相册，替代 Google Photos
笔记	Memos	轻量速记
监控	Uptime Kuma	服务存活检测
反向代理	Caddy	自动 HTTPS

八个小服务，内存总共吃掉不到 3G，还有富余。
目录结构

统一放在 /srv/docker/ 下，每个服务一个子目录：
text

/srv/docker/
├── caddy/
├── jellyfin/
├── qbittorrent/
├── syncthing/
├── immich/
├── memos/
├── uptime-kuma/
└── compose.yaml

所有配置放在一个 compose.yaml 里，方便统一启停。
Compose 编排

主文件长这样：
yaml

services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./caddy/Caddyfile:/etc/caddy/Caddyfile
      - ./caddy/data:/data
      - ./caddy/config:/config

  jellyfin:
    image: jellyfin/jellyfin:latest
    restart: unless-stopped
    user: 1000:1000
    volumes:
      - ./jellyfin/config:/config
      - ./jellyfin/cache:/cache
      - /mnt/media:/media:ro
    expose:
      - 8096

  syncthing:
    image: syncthing/syncthing:latest
    restart: unless-stopped
    user: 1000:1000
    environment:
      - PUID=1000
      - PGID=1000
    volumes:
      - ./syncthing:/var/syncthing
      - /mnt/sync:/sync
    ports:
      - "8384:8384"
      - "22000:22000/tcp"
      - "22000:22000/udp"

其余服务类似，都是 image + volumes + restart 三板斧。
反向代理

Caddy 最大好处是自动申请证书，写两行配置就能上 HTTPS。
text

blog.example.com {
    reverse_proxy jellyfin:8096
}

sync.example.com {
    reverse_proxy syncthing:8384
}

保存后 docker compose restart caddy，证书自动签好，省心。

前提是域名已经解析到这台机器的公网 IP，并且路由器上把 80 和 443 端口转发过来。
内网穿透

没有公网 IP 的话，Cloudflare Tunnel 是免费方案里最稳的。
bash

docker run -d --name cloudflared \
  --restart unless-stopped \
  --network host \
  cloudflare/cloudflared:latest tunnel --no-autoupdate run --token <你的token>

绑定后 Cloudflare 那边会自动建好子域名，也能免费用他们的证书。
遇到的问题
qBittorrent 权限

容器里的用户和宿主机不一致，下载目录写不进去。改成宿主机的 PUID/PGID：
yaml

environment:
  - PUID=1000
  - PGID=1000
  - UMASK=022

Jellyfin 硬解码

i5-8250U 自带 UHD 620，支持硬解 H.264 和 HEVC。但容器里拿不到 /dev/dri。
yaml

devices:
  - /dev/dri:/dev/dri

加上这一行就通了，转码时 CPU 从 80% 降到 20%。
Syncthing 局域网发现失败

新版 Syncthing 默认只走中继，局域网直连要开本地发现：
yaml

environment:
  - STGUIADDRESS=0.0.0.0:8384

然后手机端把电脑的 IP 手动加进节点列表。
备份策略

服务数据分两类：

    配置：几十 MB，每天打包一份到云端

    媒体：几 TB，只做本机备份，不上传

配置备份用 restic 加密后扔到 Cloudflare R2：
bash

restic -r s3:https://xxx.r2.cloudflarestorage.com/backup backup /srv/docker

媒体用 rsync 定时同步到另一块移动硬盘，每周一次。

## 接入方式

1. 把内容存为 `essays/2026-10-05.md`（**UTF-8 编码**）。
2. 复制一份 `essays/2026-10-01.html`，改名成 `essays/2026-10-05.html`。
3. 不需要改 HTML 内容，`post.js` 会自动从 URL 推导出 `2026-10-05.md`。
4. 在 `index.html` 的随笔文件夹里加一条：

```html
<details class="essay-file" data-md="essays/2026-10-05.md">
    <summary>
        <i class="fas fa-file-alt tree-icon"></i>
        <span class="tree-label">从零搭建自托管服务栈</span>
        <span class="tree-meta">2026-10-05</span>
    </summary>
    <div class="essay-body"></div>
</details>

刷新首页即可看到。
